# Платформа Smart Home Technologies

Учебный проект, реализующий микросервисную систему для интернет-магазина устройств умного дома и платформу сбора и анализа данных с этих устройств.

Проект состоит из двух логических частей:
- интернет-магазин для продажи устройств;
- система телеметрии для сбора и обработки данных от хабов и датчиков.

---

## Архитектура проекта

Приложение построено по микросервисной архитектуре.  
Каждый сервис отвечает за свою бизнес-задачу и работает со своей схемой базы данных (подход *Database per Service*).

Взаимодействие между сервисами происходит по REST и через брокер сообщений Kafka.

---

## 1. Интернет-магазин (Commerce)

Блок отвечает за продажу устройств: от отображения товаров до доставки заказа пользователю.

### Shopping Store
Сервис каталога товаров
- создание и обновление товаров
- получение списка товаров с пагинацией
- получение информации о товаре
- удаление товаров из ассортимента

### Shopping Cart
Сервис корзины пользователя
- отображение текущей корзины
- добавление и удаление товаров
- изменение количества товаров
- деактивация корзины

### Order
Сервис заказов
- оформление заказов пользователей
- управление статусами заказов
- взаимодействие со складом, оплатой и доставкой

### Warehouse
Сервис склада
- добавление товаров на склад
- прием товаров
- проверка доступности товаров по корзине
- получение адреса склада

### Payment
Сервис оплаты
- обработка оплаты заказов
- фиксация факта успешной или неуспешной оплаты

### Delivery
Сервис доставки
- создание доставки для заказа
- хранение информации о доставке

## 2. Система телеметрии и анализа

Блок отвечает за сбор и обработку данных, поступающих от хабов и датчиков пользователей.

### Collector
Сервис сбора данных
- работает как gRPC-сервер
- принимает события от датчиков и хабов
- сохраняет данные в Kafka:
    - `telemetry.sensors.v1` — события от устройств;
    - `telemetry.hubs.v1` — события хабов и сценариев.

Данные передаются в бинарном виде

---

### Aggregator
Сервис агрегации данных
- читает события датчиков из Kafka
- формирует снапшоты состояния хаба
- каждый снапшот содержит последние показания всех датчиков одного хаба
- новые версии снапшотов записываются в Kafka (`telemetry.snapshots.v1`)
- если данные не изменились — новое сообщение не создается

---

### Analyzer
Сервис анализа данных
- читает снапшоты состояния из Kafka
- анализирует показания датчиков
- принимает решения на основе заданных правил и сценариев умного дома
- формирует команды для автоматизации

## Запуск проекта

### Требования
- Java 21+
- Maven 3.8+
- Docker и Docker Compose

### Сборка проекта

```bash
mvn clean package -DskipTests
```

### Запуск сервисов
```bash
docker-compose up -d --build
```
